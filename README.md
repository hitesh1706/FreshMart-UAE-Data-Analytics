# Project Overview

FreshMart UAE is a simulated retail analytics project created to demonstrate how a Data Analyst can work from business requirements through analysis, reporting, validation, and business interpretation.

The project was approached as a business analytics assignment rather than only a dashboard-building exercise.

The analysis focused on:

- Understanding the business requirement
- Identifying the required data
- Defining metrics and filters
- Analysing the data using SQL
- Building an interactive Power BI dashboard
- Validating Power BI results against SQL
- Identifying data-quality issues
- Translating the results into business observations

The dataset was created from scratch using Python and analysed using MySQL and Power BI.

# Business-First Analytics Approach

The project was developed using a business-first approach instead of starting directly with SQL or Power BI.

## 1. Understand the Requirement

The business question was first translated into an analytical requirement.

For example, understanding repeat customer behaviour requires defining:

- What qualifies as a customer?
- What qualifies as a repeat customer?
- Which orders should be included?
- Should customers without orders be included in the repeat-customer calculation?

Examples include:

- Total Revenue
- Total Orders
- Total Customers
- Average Order Value
- Repeat Customers
- Repeat Customer %
- Repeat Customer Revenue
- Return Quantity

## 5. Build the Power BI Dashboard

Power BI was used to convert the analysis into interactive management reporting.

## 6. Validate the Results

Key Power BI results were compared with SQL results to verify that the dashboard was producing the expected outputs.

# SQL & Power BI Validation

An important part of the project was validating Power BI results against SQL instead of assuming that the dashboard was correct.

Validation included:

- Total revenue
- Total orders
- Customer counts
- Regional revenue
- Return rate
- Repeat customer calculations
- Customer segmentation
- Other major dashboard KPIs

During validation, a store-to-region mapping issue was identified in the source data.

One store was mapped to the wrong emirate in the Power BI source, which caused a regional revenue mismatch between SQL and Power BI.

The issue was traced back to the source data, corrected, and the regional results were validated again.

A customer population difference was also identified during validation. The customer master contained 10,000 customers, while 9,815 had orders. This was accounted for when calculating repeat-customer percentages.

These checks helped ensure that the final dashboard metrics were consistent with the underlying analysis.

---

# Data Quality & Problem Solving

The project included several practical data-quality challenges.

## Customer Population Difference

The customer master contained 10,000 customers, while 9,815 customers had placed orders.

Instead of treating all 10,000 customers as part of the repeat-vs-one-time calculation, the analysis separated:

- Customers with orders
- Repeat customers
- One-time customers
- Customers without orders

This resulted in a reconciled customer population.

## Store Mapping Issue

A store was mapped to the wrong emirate in the Power BI source, creating a difference in regional revenue.

The issue was identified by comparing SQL and Power BI results and tracing the mismatch back to the source data.

## Date Data Quality Issue

A date-format issue in the store source caused a Power Query refresh error.

The affected field was not required for the dashboard's analytical calculations, so it was handled without rebuilding the entire Power BI model.
